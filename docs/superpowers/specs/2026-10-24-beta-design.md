# AgentLedger 0.2 beta design / Progetto beta

## Intent / Intento

EN: The user requested implementation, optimization, review, fixes, tests and a beta published to the existing repository. Keep the developer-focused local CLI, expand repeatable collection and safe maintenance, and preserve the alpha database and privacy boundary. Assumed user remains one local developer; no external pilot or paid-provider validation is implied.

IT: L'utente richiede implementazioni, ottimizzazioni, revisioni, fix, test e beta sulla repository esistente. Si mantiene la CLI per sviluppatori, migliorando raccolta ripetibile e manutenzione sicura, compatibilità con l'alfa e minimizzazione dei dati. Utente assunto: sviluppatore locale; nessuna validazione con piloti esterni o provider a pagamento implicita.

## Selected scope / Perimetro scelto

Selected: a coherent CLI beta covering bulk collection, inspection and recoverable records. A dashboard adds another UI/runtime surface before pilot feedback; runtime bridges need separate source contracts. Both remain deferred. / Scelta una beta CLI coerente per raccolta multipla, ispezione e conservazione recuperabile. Dashboard e integrazioni runtime richiedono analisi separate e restano future.

1. **Atomic bulk import.** `import-jsonl FILE [--rates CARD]`: UTF-8/BOM JSON Lines, at most 16 MiB, 1,000 nonblank records, each at most 2 MiB. Strict duplicate-key/NaN rejection. Parse and normalize every object before opening/creating the database; a malformed response or duplicate anywhere aborts the entire batch. No partial records, raw content or file paths retained. One run UUID per imported response; source always `imported`. Existing single-response command stays supported.
2. **Transactional optimization.** Add a multi-event append API. Check schema and verify the complete historical chain once per transaction, stream that verification without retaining historical events, then append normalized prepared events sequentially. Retain unique response digest and rollback on any conflict. No unverified fast path, persistent integrity cache or altered v1 hash/schema. Standalone verification streams too; report details may still use O(n) memory.
3. **Useful reports.** `report --source {demo,imported,live} --model MODEL --run-id UUID --summary`. Filters select entire runs; model is returned usage model when present, otherwise requested decision model. Preserve associated decision/outcome events. All ledger events are verified before filtering, so corruption outside a selection fails. `event_count`/checkpoint describe the full ledger; `selected_event_count` and `filters` describe scope. Summary omits event payloads but retains totals, priced/unpriced counts, unknown/pending results and checkpoint. Markdown explains scope and incomplete pricing. A summary is not a monetary cap or invoice.
4. **Reusable checkpoints.** `checkpoint --output FILE` creates a new bounded JSON file exclusively (no overwrite), containing schema_version=1, event_count and checkpoint. `verify --checkpoint FILE` verifies the stored prefix even after valid appends; truncation below that count or a different hash at that sequence fails. Existing `--expected-head HASH` stays exact-head verification; flags are exclusive. Checkpoints are unsigned and must be kept separately in trusted storage. A zero-event checkpoint attests no nonempty history.
5. **Verified backup.** `backup DESTINATION` uses SQLite backup from one verified read transaction, refuses source path and any existing destination, creates a private destination file and verifies the copied head/count before success. No destructive restore command. Partial outputs are removed only if created by this operation; never overwrite a preexisting path. Returned JSON contains counts/head, not local paths. Read/verify/report use read-only SQLite connections; collection explicitly opens a writer. No encryption or OS sandbox claim.
6. **Hardening.** Shared strict JSON decoder for files and HTTP responses rejects duplicate keys, nonfinite numbers, invalid UTF-8 and over-nesting. Malformed provider usage becomes explicit unknown. A duplicate provider response after an attempted live request gets an unknown terminal outcome, not a silent/pending double import. Public import API cannot label supplied data as live/demo. Default-deny policy snapshots round-trip through the policy schema. Invalid imports do not create a new ledger.

## Compatibility and constraints / Compatibilità e vincoli

- Python 3.11+, standard library at runtime, complete core `agentledger/*.py` below 1,500 physical lines; GPL-3.0-or-later. No new third-party runtime assets.
- SQLite v1 tables, triggers, hashes and existing alpha events unchanged. Preserve originals in compatibility tests and compare exact hashes with the alpha tag fixture. No migrations or hash rewriting.
- Export additions are backward-compatible fields; `report` with no flags retains full details. Source `demo` stays synthetic and `imported` unverified. Metadata remains plaintext and user-supplied tariffs remain assertions.
- No paid smoke requests, automatic provider retries, new provider pricing/models, billing reconciliation, dashboard, general tool executor, signing infrastructure or automatic restore.
- Work in a local feature branch of the clean, explicitly selected checkout; no concurrent implementation worker is needed. One independent review before publication. User authorized publication to the existing repository; verify checks, all reachable history and assets before publishing a beta prerelease.

## Modules and verification / Moduli e verifiche

`jsonio.py`: shared strict bounded JSON/JSONL and exclusive checkpoint writes. `storage.py`: streamed hash verification, transaction batches, prefix checkpoints and verified backup. `service.py`: collection boundaries, bulk normalization, source restriction and filtered reports. `cli.py`: commands and safe errors. `domain.py`/`provider.py`: validation fixes and strict transport parsing. The event contract remains v1; checkpoint file schema is also v1 but separate.

Acceptance: existing alpha tests stay green; bulk corruption/duplicates roll back; concurrent batches cannot double-count; denied/error paths stay private; filters preserve context and reject hidden corruption; summary omits events; prefix checkpoints accept legitimate appends and reject truncation; backup source/destination contents and checkpoints agree; existing destinations remain byte-identical on failures. Reproduce the documented offline workflow from an installed wheel and source archive, benchmark single vs batch collection locally, run Windows/Linux CI on 3.11/3.14, review independently, publish checksummed `v0.2.0-beta.1` / package `0.2.0b1`.

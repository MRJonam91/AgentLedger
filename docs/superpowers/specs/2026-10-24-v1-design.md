# AgentLedger 1.0 design / Progetto 1.0

## Intent / Intento

EN: Complete the existing local developer CLI as stable 1.0, rather than expand into a dashboard, general runtime or billing service. The user authorized implementation, fixes, documentation alignment and publication to the existing public repository. Keep v1 SQLite/hash compatibility, zero runtime dependencies and explicit limits of local evidence.

IT: Completare la CLI locale per sviluppatori come 1.0 stabile, senza estenderla a dashboard, runtime generico o servizio di fatturazione. L'utente autorizza implementazione, fix, allineamento documenti e pubblicazione nella repository esistente. Conservare compatibilità SQLite/hash v1, zero dipendenze e limiti espliciti delle evidenze locali.

## Selected changes / Modifiche scelte

1. `init`: explicitly create an empty ledger, verify an existing ledger without resetting it, return a safe JSON count/checkpoint. Repeated initialization preserves events and existing database bytes. Invalid/corrupt existing databases fail closed.
2. `report --output FILE`: create-only UTF-8 JSON/Markdown export, supporting existing filters and summary. Existing files, including the source database, are never overwritten. Stdout becomes a receipt with format, counts and checkpoint, not a local path. Default stdout reports remain unchanged. Errors clean up only the new file owned by that operation.
3. Request preflight: validate nonempty bounded UTF-8 prompt, exact model syntax and bounded output count before ledger creation. Reject malformed requests without creating directories or a database. Reuse one validator from CLI and service. No network, policy or pricing changes.
4. Stable input/output boundaries: strict JSON decoding explicitly rejects wrong input types and invalid Unicode. Exclusive writes retain fsync, no-overwrite and failure cleanup. Preserve existing error codes and add only documented commands/options.
5. Regression verification: separate-process concurrent imports from a new database; whole-transaction duplicate rollback; real loopback HTTP tests of request body, strict response parsing and redirect refusal. The test-only URL seam never changes the production fixed HTTPS endpoint. Preserve frozen alpha compatibility and beta workflows. No paid provider calls or TLS/live-account certification.
6. Release controls: explicit public source roots and package exclusions, archive-to-commit comparisons, notices, checksums, history/identity scan, fresh installed-wheel workflow and extracted-source checks. Local operational material is outside the public source contract. Publish stable `v1.0.0` / package `1.0.0`, with no prerelease flag, and verify repository public visibility.

## Compatibility / Compatibilità

- Python 3.11+, standard library at runtime, GPL-3.0-or-later; complete `agentledger/*.py` under 1,500 physical lines.
- SQLite schema/hash v1, existing records and exact/prefix checkpoints unchanged. No migration, destructive restore or silently rewritten data.
- Decimal cost calculation and source labels demo/imported/live retained. Full chain verified before report filtering/export; `init` on an existing ledger verifies its chain too.
- Local one-user trust boundary, plaintext metadata, unsigned checkpoints and no monetary budget enforcement remain explicit. Reports still materialize O(n) historical events.
- APIs/models/pricing remain unchanged; live integration and external user feedback are pending validation activities, not prerequisites silently claimed as done.

## Completion / Completamento

All beta tests plus 1.0 regressions pass; init/export/preflight and no-overwrite failures are covered; independent review has no unresolved material findings; static/project/history checks and Windows/Linux Python 3.11/3.14 CI pass on the release revision; inspected wheel/source match that revision and remote digests. Align README EN/IT, architecture, event contract, threat model, support, changelog, roadmap and release evidence. Close the 1.0 implementation plan; future integrations are separately scoped work.

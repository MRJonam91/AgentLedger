# AgentLedger Beta Implementation Plan

> For agentic workers: execute inline with executing-plans and request one independent read-only review before release.

**Goal:** Ship a backward-compatible CLI beta for bulk ingestion, scoped reports and safe ledger maintenance.
**Architecture:** Shared strict input boundary, streamed integrity verification inside SQLite transactions, source-separated accounting, explicit export/checkpoint/backup operations.
**Tech stack:** Python 3.11+ standard library; unittest, mypy, setuptools/build for development only.
**Spec:** `docs/superpowers/specs/2026-10-24-beta-design.md`.

## Global constraints

- Python 3.11+, zero runtime dependencies, `agentledger/*.py` < 1,500 physical lines.
- No prompt/output/key/raw exception/file path persistence; default deny before provider effects.
- Exact Decimal tariffs, separate demo/imported/live assertions, no paid smoke calls.
- Existing SQLite v1 and alpha hashes remain readable without migration.
- Bilingual user docs, GPL-3.0-or-later, source/archive/history and remote release verification.

## Review focus

1. Duplicate or bad final batch item: zero partial writes, including concurrent collectors.
2. Checkpoint refers to earlier history: allow legitimate appends but reject deleted/changed prefixes.
3. Backup errors/existing destination: never replace or remove somebody else's file.
4. Filtered report: verify hidden records and retain decision/outcome context.
5. Hostile JSON/provider failures: bounded parsing, fixed safe errors and no source-label laundering.

# AgentLedger Alpha Implementation Plan

> For agentic workers: execute inline using executing-plans; request one independent review before release.

**Goal:** A usable local accounting and policy ledger for one OpenAI text agent.
**Architecture:** Validate at collection boundaries, persist only normalized records in a transactional SQLite hash chain, and export verified reports. Keep HTTP transport separate from policy orchestration.
**Tech stack:** Python 3.11+ standard library; setuptools for packaging, unittest for checks.
**Spec:** `docs/superpowers/specs/2026-10-23-alpha-design.md`.

## Global constraints

- Python 3.11+; standard library only at runtime.
- No prompt, generated text, credentials, raw exceptions or input paths in the ledger.
- Default deny; no provider calls before an allowed decision is durably recorded.
- Demo/import/live accounting separated; calculated costs are not invoices.
- Runtime core below 1,500 physical lines, measured across `agentledger/*.py`.
- IT/EN user documentation in the same release; GPL-3.0-or-later and required funding metadata.

## Review focus

1. Invalid numbers, missing usage and cache subsets: reject before import, mark live unknown after provider contact.
2. Denied requests and network/provider errors: no paid call on deny; no raw error strings retained.
3. Duplicate concurrent imports and interrupted writes: unique digest and single append transaction.
4. Modified/truncated database and wrong schema: verified reads and external checkpoint check.
5. Rate/model mismatches and unpriced data: never silently represent unknown cost as zero.
